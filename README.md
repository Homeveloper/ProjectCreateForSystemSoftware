# cfgtool

Консольная утилита для проверки и преобразования конфигураций в форматах
YAML и JSON. Учебный продукт курса по безопасной разработке,
вариант 8 — «CLI для обработки конфигураций».

## Возможности

| Команда | Назначение |
|---|---|
| `validate <файл> [--schema <схема.json>]` | проверка синтаксиса и соответствия схеме |
| `summary <файл>` | краткое описание без записи результата |
| `convert <файл> [-o <имя>]` | преобразование YAML в JSON и обратно |
| `merge <файл> <файл> [...] [-o <имя>]` | объединение конфигураций по порядку |
| `redact <файл> [-o <имя>]` | скрытие значений секретных полей |
| `version` | версия сборки |
| `help` | справка |

Если `-o` не указан, результат выводится в стандартный поток вывода.

## Флаги

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `-o` | — | имя файла результата |
| `--out-dir` | `.` | каталог для результата; выход за его пределы отклоняется |
| `--force` | выкл. | разрешить замену существующего файла результата |
| `--schema` | — | файл схемы для `validate` |
| `--verbose` | выкл. | подробности разбора; секреты в выводе скрываются |
| `--max-bytes` | `10485760` | предельный размер входного файла |
| `--max-depth` | `64` | предельная глубина вложенности |

## Коды завершения

Причины отказа различаются по коду, чтобы сценарий автоматизации мог
реагировать на них, не разбирая текст сообщения.

| Код | Значение |
|---|---|
| `0` | успешно |
| `1` | ошибка в аргументах командной строки |
| `2` | входной файл не прочитан или не разобран |
| `3` | конфигурация нарушает схему |
| `4` | результат не записан |

## Сборка и запуск

```
go build -o bin/cfgtool ./cmd/cfgtool
./bin/cfgtool validate testdata/app.yaml --schema testdata/schema.json
```

## Примеры

```
# проверить конфигурацию по схеме
cfgtool validate testdata/app.yaml --schema testdata/schema.json

# посмотреть состав конфигурации, ничего не записывая
cfgtool summary testdata/app.yaml

# преобразовать YAML в JSON в каталог build
cfgtool convert testdata/app.yaml -o app.json --out-dir build

# заменить уже существующий результат
cfgtool convert testdata/app.yaml -o app.json --out-dir build --force

# наложить окружение на базовую конфигурацию
cfgtool merge testdata/app.yaml testdata/override.yaml -o effective.yaml --out-dir build

# получить копию без секретов, пригодную для передачи
cfgtool redact testdata/app.yaml -o app.public.yaml --out-dir build
```

## Обработка недоверенного ввода

Файл конфигурации считается недоверенным. Продукт:

- ограничивает размер входных данных и глубину вложенности;
- оценивает глубину до разбора, поскольку слишком глубокая вложенность
  исчерпывает стек внутри синтаксического анализатора;
- полагается на `gopkg.in/yaml.v3`, которая ограничивает раскрытие
  псевдонимов YAML;
- не включает разбираемые данные в сообщения об ошибках;
- заменяет маской значения полей, опознанных как секретные, в отчётах
  о нарушениях схемы, в подробном выводе и в кратком описании.

## Обращение с файлом результата

- имена, выводящие за пределы `--out-dir`, отклоняются;
- абсолютные пути отклоняются;
- запись через символьную ссылку и поверх каталога отклоняется;
- существующий файл не заменяется без явного `--force`;
- запись выполняется через временный файл с последующим переименованием,
  поэтому прерывание не оставляет частично записанного результата;
- результат создаётся с правами `0600`, каталоги — с правами `0700`.

Подробнее: [SECURITY.md](SECURITY.md).

## Поддерживаемое подмножество схемы

Схема задаётся файлом JSON и поддерживает ключевые слова
`type`, `required`, `properties`, `items`, `enum`, `pattern`,
`minimum`, `maximum`. Пример — [testdata/schema.json](testdata/schema.json).

## Разработка

```
go test ./...                   # тесты, включая негативные проверки безопасности
scripts/check.sh <каталог>      # полный набор проверок, отчёты в evidence/
scripts/reproduce-baseline.sh   # повторить проверки исходного состояния
scripts/release.sh <версия>     # сборка выпуска с контрольными суммами
```

Результаты проверок и решение о выпуске — в [project.md](project.md).
