Пропускаемые на Windows тесты выполняются в CI на Linux: два на права
доступа POSIX и один на отказ от записи через символьную ссылку.

## Как воспроизвести

```
scripts/reproduce-baseline.sh             # исходное состояние целиком
scripts/check.sh <имя-каталога>           # полный набор проверок
scripts/probe-alias-bomb.sh <имя-каталога> # целевой эксперимент
scripts/release.sh <версия>               # сборка выпуска
```

Версии инструментов закреплены в `.github/workflows/ci.yml`:
staticcheck v0.8.1, govulncheck v1.8.0, gosec v2.29.0.

Сверка воспроизведённого прогона исходного состояния с сохранёнными
отчётами совпала по всем показателям, кроме времени выполнения.

## Состав отчётов

| Файл | Инструмент | Что показывает |
|---|---|---|
| `gofmt.txt` | gofmt | файлы с нарушением форматирования |
| `vet.txt` | go vet | подозрительные конструкции |
| `test.txt` | go test | подробный результат тестов |
| `cover.txt`, `coverage.out`, `coverage-total.txt` | go test -cover | покрытие тестами |
| `staticcheck.txt` | staticcheck | статический анализ |
| `gosec.txt` | gosec | типовые дефекты безопасности в коде |
| `govulncheck.txt` | govulncheck | известные уязвимости в зависимостях |
| `security-tests.txt` | go test | негативные проверки безопасности |
| `dos-alias-bomb.txt` | scripts/probe-alias-bomb.sh | измеренное усиление при разборе псевдонимов |
| `release-artifacts.txt` | scripts/release.sh | контрольные суммы и состав зависимостей выпуска |

Интерпретация результатов, триаж и решение о выпуске — в [../project.md](../project.md).
